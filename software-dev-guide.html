2Version Control (Git)

Think of Git as a save game system for your code — branching timelines you can merge back together.

  main (production-ready code)
  ━━━━●━━━━━━━━●━━━━━━━━━━━━●━━━━━━━━●━━━━━━━━►
       │                      ▲        ▲
       │  feature/login       │        │
       └──●───●───●───●──────┘        │
                      │                │
                      │  hotfix/crash  │
                      └──●─────────────┘

  ● = a commit (a snapshot of your code at a point in time)
  ━ = branch (a parallel timeline)
Branch
A parallel copy of the code where you work without disturbing others.
Commit
A saved checkpoint — "here's what I changed and why."
Merge
Bringing your branch back into the main timeline.

3Pull Request (PR)

A PR is a "please review my work" request before code enters the main branch.

  ┌─────────────────────────────────────────────┐
  │  PR #42: Add user login page                │
  ├─────────────────────────────────────────────┤
  │                                             │
  │  Author: Alice        Reviewers: Bob, Carol │
  │  Branch: feature/login → main               │
  │                                             │
  │  Files changed: 5     +120 lines  -30 lines │
  │  ┌───────────────────────────────────────┐  │
  │  │  - old code (red)                     │  │
  │  │  + new code (green)                   │  │
  │  └───────────────────────────────────────┘  │
  │                                             │
  │  Bob:   "Looks good, but add validation"    │
  │  Alice: "Fixed! Updated the PR"             │
  │  Carol: "Approved ✓"                        │
  │                                             │
  │  [  Merge PR  ]                             │
  └─────────────────────────────────────────────┘

4CI/CD (Continuous Integration / Deployment)

A robot assembly line that automatically checks and ships your code.

  You push code
       │
       ▼
  ┌──────────────────── CI (Continuous Integration) ────────────────────┐
  │                                                                     │
  │   📥 Pull code → 🔨 Build → 🧪 Run tests → 🔍 Lint/Style check      │
  │                                                                     │
  │   Any step fails? ──── ❌ STOP. Notify developer.                   │
  │   All pass?       ──── ✅ Continue...                               │
  │                                                                     │
  └──────────────────────────────┬──────────────────────────────────────┘
                                 │
                                 ▼
  ┌──────────────────── CD (Continuous Deployment) ─────────────────────┐
  │                                                                     │
  │   📦 Package app → 🚢 Deploy to staging → ✅ Deploy to production   │
  │                                                                     │
  └─────────────────────────────────────────────────────────────────────┘
CI = "Does my code break anything?" (automated checking)
CD = "Ship it automatically if everything's green."

6Serverless

Despite the name, there are servers — you just don't manage them.

Traditional Server

┌──────────────────┐
│  Your Server     │
│  ┌────────────┐  │
│  │ Your Code  │  │
│  └────────────┘  │
│                  │
│  Running 24/7    │
│  even when idle  │
│  💰💰💰           │
│  You manage OS,  │
│  updates, scaling│
└──────────────────┘

Serverless

Request comes in
      │
      ▼
┌──────────┐
│ Function │  ← spins up
│ runs     │
│ responds │
└──────────┘  ← shuts down

No request? Nothing runs.
💰 (pay per use only)
Cloud handles the rest.

Examples: AWS Lambda, Cloudflare Workers, Vercel Functions.

7Containers & Docker

A container is a lunchbox for your app — everything it needs, packed together.

  ┌─────────── Container ───────────┐
  │                                 │
  │   Your App                      │
  │   + Dependencies (Node, etc.)   │
  │   + Config files                │
  │   + System libraries            │
  │                                 │
  │   "Everything needed to run,    │
  │    identical everywhere"        │
  │                                 │
  └─────────────────────────────────┘

  Works on my machine ──► Works EVERYWHERE
  (dev, staging, prod — all identical)
Dockerfile
The recipe.
Image
The packaged lunchbox.
Container
A running instance of that lunchbox.

9API (Application Programming Interface)

A menu at a restaurant — you don't go into the kitchen, you just order.

  Your App                          Someone's Server
  ━━━━━━━━                          ━━━━━━━━━━━━━━━

  "I'd like the                ┌────────────────────┐
   weather for London"         │                    │
        │                      │   🍳 Kitchen       │
        │   GET /weather       │   (complex logic,  │
        │   ?city=London       │    databases, etc.)│
        ├─────────────────────►│                    │
        │                      │   You don't see    │
        │   { "temp": 15,      │   any of this      │
        │     "sky": "cloudy"} │                    │
        │◄─────────────────────┤                    │
        │                      └────────────────────┘
  "Thanks, I'll display
   that to my user"
REST
Uses HTTP verbs (GET, POST, PUT, DELETE) like web addresses.
GraphQL
You specify exactly what data you want back.
Webhook
Reverse API — the server calls YOU when something happens.

10Infrastructure as Code (IaC)

Instead of clicking buttons in a dashboard, you describe your infrastructure in files.

Manual (ClickOps)

👆 Click "Create Server"
👆 Click "Add Database"
👆 Click "Set Firewall"
👆 Forget what you did
👆 Can't reproduce it

IaC (Terraform)

resource "server" {
  cpu      = 4
  memory   = "16GB"
  database = true
  firewall = ["443","80"]
}

$ terraform apply
✅ Reproducible. Versioned.

11The Full E2E Flow — A Day in the Life

#StepWhat happens
1Ticket"Users can't reset passwords" (Jira / Linear)
2Branchgit checkout -b fix/password-reset
3CodeWrite the fix locally
4TestRun tests locally: npm test
5Commitgit commit -m "Fix password reset flow"
6Pushgit push origin fix/password-reset
7PROpen Pull Request, request review
8CI runsRobot builds & tests automatically ✅ ❌
9Code reviewTeammate reads code, leaves comments
10MergePR approved → merge to main
11CD deploysAutomatically ships to staging → production
12MonitorWatch dashboards, logs, error tracking
13Done✅ Ticket closed, users can reset passwords
